# Vitals — AI-Powered BMI Health Tracker

A BMI calculator built as a small full-stack web app rather than a plain script:
a live gauge visualization, persistent multi-user history, a trend chart, and
**AI-generated personalized health insights** powered by Google's Gemini API.

Built for the **Oasis Infobyte Python Programming Internship** — Task: BMI Calculator (Advanced Tier).

---

## Features

- **Instant BMI calculation** with input validation (rejects non-numeric, negative, or clearly wrong values — e.g. height entered in cm instead of metres)
- **Custom gauge visualization** — a needle sweeps across colour-coded zones (Underweight / Normal / Overweight / Obese)
- **Multi-user support** — records are saved per name, so multiple people can track separately
- **Persistent history** stored in a database, viewable as a table
- **Trend chart** (Chart.js) plotting a user's BMI over time across all their logged entries
- **AI health insights** — a short, personalized, encouraging note generated by Gemini based on your current BMI *and* your trend across past entries
- **Graceful degradation everywhere** — if the AI key is missing, the network is down, or the database write fails, the app tells you clearly instead of crashing

## Running Locally

**1. Clone your repo and enter the project folder:**
```bash
cd OIBSIP/Python-Task2-BMICalculator
```

**2. Install dependencies:**
```bash
pip install -r requirements.txt
```

**3. (Optional) Enable AI insights:**
Copy `.env.example` to `.env` and add a free Gemini API key from [ai.google.dev](https://ai.google.dev):
```bash
cp .env.example .env
# then edit .env and paste your key
export GEMINI_API_KEY=your_key_here   # or use python-dotenv / your shell profile
```
The app works perfectly fine **without** this — it just won't show AI notes.

**4. Run the app:**
```bash
python app.py
```
Visit **http://localhost:5000** in your browser.

A local `bmi_records.db` SQLite file will be created automatically on first run.

## Deploying to Vercel

Vercel's Python runtime executes serverless functions with an **ephemeral filesystem** —
a local SQLite file will not persist reliably between requests once deployed. This project
handles that automatically:

- **No `DATABASE_URL` set** → falls back to local SQLite (fine for a quick demo deploy, but history may reset between cold starts)
- **`DATABASE_URL` set** → automatically switches to PostgreSQL for real persistence

### Steps

1. **Push this project to your `OIBSIP` GitHub repo** (in the folder `Python-Task2-BMICalculator/` per the internship's naming convention).

2. **Import the repo into Vercel** ([vercel.com/new](https://vercel.com/new)) — Vercel will detect `vercel.json` automatically.

3. **Set environment variables** in the Vercel project dashboard (Settings → Environment Variables):
   | Variable | Required? | Value |
   |---|---|---|
   | `GEMINI_API_KEY` | Optional | Your key from [ai.google.dev](https://ai.google.dev) |
   | `DATABASE_URL` | Optional (recommended) | A free Postgres connection string from [neon.tech](https://neon.tech) or [supabase.com](https://supabase.com) |

4. **Deploy.** Vercel builds `app.py` using `@vercel/python` and routes all traffic to it.

That's it — the same codebase runs identically locally and in production.

## API Reference

| Method | Route | Description |
|---|---|---|
| `GET` | `/` | Serves the frontend |
| `POST` | `/api/calculate` | Body: `{username, weight, height}` → returns BMI, category, AI insight, and full history |
| `GET` | `/api/history/<username>` | Returns all saved records for a user |
| `GET` | `/api/users` | Returns all usernames with saved records |

## Design Notes

The interface avoids a generic "form + result box" layout in favour of a gauge instrument —
BMI is a single continuous number, so a dial that sweeps between zones communicates the
result more intuitively than a plain text label, while still meeting the checklist requirement
for colour-coded feedback.
