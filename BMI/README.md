# Vitals+ — AI Health Intelligence Platform

A BMI calculator reimagined as a full-stack health analytics platform: a live gauge
visualization, persistent multi-user history, a multi-metric trend chart, a **Hybrid AI
insight engine**, and a **predictive BMI forecasting model** — all wrapped in a
health-tech interface.

Built for the **Oasis Infobyte Python Programming Internship** — Task: BMI Calculator (Advanced Tier).

## What makes this different (USPs)

Most BMI calculators stop at "weight ÷ height²". This project treats BMI tracking as a
small data product, with two features designed to stand out in a review:

### 1. Hybrid AI Insight Engine — never fails, never leaks
Health notes are generated by Google Gemini when available. But relying on a single
third-party AI call is fragile — free-tier quotas get rate-limited (`429`), keys expire,
networks drop. So every request goes through a small resilience layer:

- On a Gemini success → returns the AI-written note, tagged `source: "ai"`.
- On a `429`/`5xx` → **one fast retry**, then falls back automatically.
- On any other failure (timeout, network error, missing key) → falls back automatically.
- **Fallback**: a deterministic, rule-based local generator (`_local_insight` in
  `bmi_logic.py`) builds a genuinely personalized note from the user's category, their
  own BMI trend, and their calorie estimate — tagged `source: "local"`.

The UI keeps this invisible to the end user (just a clean "Personalized Insight" note) —
the AI/local distinction is surfaced in the API response (`ai_insight.source`) and this
README for a technical reviewer, not narrated in the product itself. Critically, **no
exception text or API key is ever returned to the browser**; errors are logged
server-side only.

### 2. Predictive BMI Forecasting
`forecast_bmi_trend()` fits a least-squares linear regression over a user's own logged
BMI-vs-time history, then:
- Projects BMI **30 days forward** if the current trend continues.
- If a goal weight is set, estimates **ETA to goal** in days, using the fitted
  weight-change slope (kg/day).
- Flags confidence as `preliminary` (< 5 entries) vs `higher` (≥ 5 entries), and only
  activates once entries span more than half a day, so it never fabricates a trend from
  noise.

This is intentionally a simple, explainable model (not a black-box call to an external
API) — appropriate for a final-year-level project where you may be asked to explain the
math in a review.

### 3. Transparent Health Score
`compute_health_score()` produces a 0-100 composite score from four deterministic,
inspectable components — **not** an AI guess:

| Component | Weight | What it measures |
|---|---|---|
| BMI standing | 40 | Distance from the center of the healthy BMI range |
| Consistency | 20 | Logging streak — rewards adherence, not just the reading |
| Trend direction | 20 | Whether the regression-fit trend is moving the right way for the user's category |
| Goal progress | 20 (only if a goal is set) | % progress toward the user's own goal weight |

If no goal is set, the remaining components are proportionally rescaled so the score
always totals out of 100. The full breakdown (each component's raw score and cap) ships
in the API response and renders as a bar breakdown in the UI — every point is traceable,
by design, so it can survive the question "how is this calculated?" in a review.

## Features

- **Instant BMI calculation** with input validation (rejects non-numeric, negative, or clearly wrong values — e.g. height entered in cm instead of metres)
- **Custom gauge visualization** — a needle sweeps across colour-coded zones (Underweight / Normal / Overweight / Obese)
- **Metric / Imperial unit toggle** — enter kg & m, or lb & ft-in, interchangeably
- **Optional health dashboard** — add age, gender, and activity level to unlock:
  - **BMR** (Basal Metabolic Rate, via the Mifflin-St Jeor equation)
  - **Estimated daily calorie needs** (BMR × activity multiplier)
  - **Body fat % estimate** (Deurenberg formula)
  - **Healthy weight range** for your height
  - **Water intake recommendation**
- **Goal tracking** — set a target weight and see a live progress bar toward it
- **Streaks & achievement badges** — consecutive-day logging streaks and unlockable milestones (First Step, Consistent Tracker, 7-Day Streak, etc.)
- **Community stats strip** — anonymous, aggregate stats across all users (total entries, people, average BMI)
- **Dark mode toggle**, remembered across visits
- **Multi-user support** with returning-user recognition — type a name you've used before and it greets you and loads your history automatically
- **Persistent history** stored in a database, viewable as a table, with a **Clear my history** option
- **Multi-metric trend chart** (Chart.js) — toggle between BMI / Weight / Calories over time
- **AI health insights** — a short, personalized, encouraging note generated by Gemini, aware of your BMI, BMR, calorie estimate, and your trend across past entries
- **Real PDF report download** (server-generated, not just browser print) and **CSV export** of your full history
- **Copy Summary** and native **Share** (on supported devices/browsers)
- **Custom toast notifications and confirmation modal** — no jarring browser `alert()`/`confirm()` popups
- **Graceful degradation everywhere** — if the AI key is missing, quota-limited, the network is down, or the database write fails, the app degrades to a safe, clear message and *never* leaks internal errors, connection strings, or API keys to the browser
- **Hybrid AI Insight Engine** with a transparent AI/Local source badge (see USPs above)
- **Predictive BMI Forecasting** — 30-day trend projection + goal ETA via linear regression (see USPs above)

## Running Locally

**1. Clone your repo and enter the project folder:**
```bash
cd OIBSIP/Python-Task2-BMICalculator
```

**2. Install dependencies:**
```bash
pip install -r requirements.txt
```

**3. (Optional) Enable AI insights:**
Copy `.env.example` to `.env` and add a free Gemini API key from [ai.google.dev](https://ai.google.dev):
```bash
cp .env.example .env
# then edit .env and paste your key
export GEMINI_API_KEY=your_key_here   # or use python-dotenv / your shell profile
```
The app works perfectly fine **without** this — it just won't show AI notes.

**4. Run the app:**
```bash
python app.py
```
Visit **http://localhost:5000** in your browser.

A local `bmi_records.db` SQLite file will be created automatically on first run.

## Deploying to Vercel

Vercel's Python runtime executes serverless functions with an **ephemeral filesystem** —
a local SQLite file will not persist reliably between requests once deployed. This project
handles that automatically:

- **No `DATABASE_URL` set** → falls back to local SQLite (fine for a quick demo deploy, but history may reset between cold starts)
- **`DATABASE_URL` set** → automatically switches to PostgreSQL for real persistence

### Steps

1. **Push this project to your `OIBSIP` GitHub repo** (in the folder `Python-Task2-BMICalculator/` per the internship's naming convention).

2. **Import the repo into Vercel** ([vercel.com/new](https://vercel.com/new)) — Vercel will detect `vercel.json` automatically.

3. **Set environment variables** in the Vercel project dashboard (Settings → Environment Variables):
   | Variable | Required? | Value |
   |---|---|---|
   | `GEMINI_API_KEY` | Optional | Your key from [ai.google.dev](https://ai.google.dev) |
   | `DATABASE_URL` | Optional (recommended) | A free Postgres connection string from [neon.tech](https://neon.tech) or [supabase.com](https://supabase.com) |

4. **Deploy.** Vercel builds `app.py` using `@vercel/python` and routes all traffic to it.

5. **Before you submit: confirm the deployment is actually public.** Vercel's
   *Deployment Protection* (Settings → Deployment Protection) can silently gate your
   production URL behind a Vercel SSO login for anyone who isn't a team member — a
   reviewer clicking your link would just hit a login wall with no way in. Set it to
   **"Only Preview Deployments"** (or off), then open your production URL in an
   **incognito window** to confirm it loads with no login prompt.

That's it — the same codebase runs identically locally and in production.

## API Reference

| Method | Route | Description |
|---|---|---|
| `GET` | `/` | Serves the frontend |
| `POST` | `/api/calculate` | Body: `{username, weight, height, age?, gender?, activity_level?}` → returns BMI, category, all health metrics, AI insight, streak, achievements, goal progress, and full history |
| `GET` | `/api/history/<username>` | Returns all saved records for a user |
| `DELETE` | `/api/history/<username>` | Deletes all saved records for a user |
| `GET` | `/api/users` | Returns all usernames with saved records |
| `POST` | `/api/goal` | Body: `{username, goal_weight}` → sets/updates a goal, returns current progress |
| `GET` | `/api/goal/<username>` | Returns a user's goal weight and current progress |
| `GET` | `/api/community-stats` | Returns anonymous aggregate stats (total entries, users, average BMI) |
| `GET` | `/api/report/<username>` | Downloads a server-generated PDF health report |
| `GET` | `/api/export/<username>` | Downloads the user's full history as CSV |

`ai_insight` in the `/api/calculate` response is `{available, message, source}` where
`source` is `"ai"` or `"local"`. `forecast` is
`{available, trend_direction, bmi_change_per_week, projected_bmi, projected_days,
confidence, goal_eta_days?, goal_eta_date?}` (or `{available: false, reason}` if there
isn't enough history yet). `health_score` is `{score, components: [{label, score, max}]}`.

## Security note

An earlier version of this app returned raw exception text (including the full request
URL, which embeds the Gemini API key) straight to the browser whenever the Gemini API
call failed — visible to anyone who triggered a `429`. This has been fixed:

- `bmi_logic.get_ai_insights()` never raises, and never returns exception text
- All Flask routes that touch the database log the real error server-side only
  (`print(...)`, visible in Vercel's function logs) and return a generic message to the client
- **If you deployed a version with the old behaviour, treat your `GEMINI_API_KEY` as
  compromised and regenerate it** at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

## Design Notes

The interface avoids a generic "form + result box" layout in favour of a gauge instrument —
BMI is a single continuous number, so a dial that sweeps between zones communicates the
result more intuitively than a plain text label, while still meeting the checklist requirement
for colour-coded feedback.
